# 记忆管理

## 该记什么（主动记，不用等用户说）
- **用户偏好**：语言偏好、代码风格、工具选择、沟通方式、禁忌。
  ```
  memory(action="remember", kind="preference", title="代码风格偏好",
         content="用户偏好 Python 类型注解 + Google 风格 docstring", importance=0.9, pinned=true)
  ```
- **项目背景**：目录约定、构建命令、部署方式、环境特殊性。
- **重要决策**：为什么选 A 不选 B，当时的约束是什么。
- **已解决的问题**：某个命令在本机不可用、某个问题的正确解法。

## 不该记什么
- 一次性的临时信息（这些留在会话里就够）。
- 已在项目文件里写清楚的东西（README、配置注释）——重复记会过时。
- 用户随口一说、未经确认的猜测。
- 密钥、密码、token（**绝对不要**写入记忆）。

## 怎么组织（关键）
1. **标题要短且唯一**，方便后续检索覆盖：`"Python 环境路径"` 而不是 `"关于 Python 的一些信息"`。
2. **内容自包含**：不要把"上面提到的那个"写进记忆——记忆脱离上下文后要能独立读懂。
3. **一条一事**：一条记忆只讲一件事。塞太多会降低检索精度。
4. **写明时间和版本**：`"2026-09 实测：xxx 路径是 D:\...，"`——记忆会过时，标注时间让后来者能判断。
5. **打标签**：便于按类别召回。

## 更新而不是新增
同一个事实变了，要用 `action="update"` 改原条目（或 `remember` 同一 `title` 覆盖），
不要留两条互相矛盾的记忆。发现记忆错了，`action="forget"` 删掉或改正。

## 回忆
- 每轮开始前，相关记忆会自动注入到 `<memory>` 块里。
- 需要更精确的检索时用 `memory(action="recall", query="...")`。
- **记忆可能过时**：涉及路径、版本、价格这类会变的信息，用记忆当线索，但要用工具**实测验证**再下结论。
- 不要在回复里说"根据我的记忆"这种话——直接把内容用起来就好。
