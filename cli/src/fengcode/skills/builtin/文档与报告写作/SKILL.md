# 文档与报告写作

## 通用原则
1. **先定读者**：给谁看？（开发者 / 决策者 / 最终用户）决定详略与术语密度。
2. **结论先行**：第一段就把最重要的话说完。不要"随着时代的发展……"式铺垫。
3. **具体胜过形容**：写"启动时间从 3.2s 降到 0.4s"，不写"性能大幅提升"。
4. **能省就省**：一句能说清就别写三句。删掉所有不承载信息的句子。

## README 标准结构
```
# 项目名
> 一句话说明它是什么、解决什么问题

## 特性（3-6 条，每条一行）
## 快速开始（能复制粘贴就跑通的命令）
## 安装（含依赖与前置条件）
## 使用（最常见场景的示例）
## 配置（关键配置项表格）
## 项目结构（目录树 + 简述）
## 常见问题
## 许可证
```

## 技术方案结构
```
# 方案名
## 背景与问题（为什么要做）
## 目标与非目标（明确边界）
## 方案设计（架构图 + 关键决策及理由）
## 备选方案对比（至少 2 个，说明为什么没选）
## 实施计划（分阶段，可交付物明确）
## 风险与应对
## 验收标准（可量化）
```

## 写作纪律
- 中文写作：用中文标点（，。：；""），中英文之间加空格，数字与单位之间加空格。
- 列表项保持结构一致（都是动词开头，或都是名词）。
- 代码块标注语言；命令要给可直接复制的完整形式。
- 不要写"显然""众所周知""简单来说"这类词——要么解释清楚，要么删掉。
- 不确认的信息标注"待确认"，不要凭印象写。
