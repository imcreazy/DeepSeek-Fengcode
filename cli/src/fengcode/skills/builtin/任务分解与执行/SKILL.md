# 任务分解与执行

## 1. 先确认"做完"是什么样
写下一句可验证的完成标准。例：
- ❌ "优化一下这个页面"
- ✅ "首屏加载 < 1s，320px 宽下不横向滚动，控制台无报错"

标准不明确且无法用合理默认值推进时，用 `ask_user` 问一次（带 2-4 个选项），**不要反复追问**。

## 2. 拆步骤并写进任务清单
```
todo(action="set", items=[
  {"title": "摸清现有实现", "detail": "读 xxx 文件，确认改动点", "status": "in_progress"},
  {"title": "实现改动", "detail": "..."},
  {"title": "验证", "detail": "跑 xxx 测试 / 打开页面截图"},
])
```
规则：
- 每一步都要**能独立验证**（做完能说"这步确实成了"）。
- 步骤数控制在 3-8 个；超过 10 个说明拆得太细或目标太大。
- 有依赖关系的要显式写出来。

## 3. 执行纪律
- 做完一步就 `todo(action="update", id=..., status="completed")`，再开始下一步。
  不要攒到最后一次性更新。
- **每步做完立刻验证**，不要等全部做完才测——错误会叠加。
- 遇到与预期不符：停下来，说明差异，调整计划，而不是硬推。
- 卡住了：说明卡在哪、试过什么、需要什么。不要假装完成。

## 4. 长任务用目标机制
需要跨多轮才能完成的大任务：
```
goal(action="set", objective="...", max_rounds=10)
...
goal(action="progress", note="已完成 X，下一步 Y")
goal(action="complete")
```

## 5. 汇报
- 全部完成：给结果 + 验证方式 + 已知限制。
- 部分完成：明确说哪些完成、哪些没做、为什么。
- 失败：说清楚失败原因和下一步建议，不要粉饰。
- **不要声称"已完成"而实际没验证。**
