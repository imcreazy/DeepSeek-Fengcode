# 深度研究

## 检索策略（关键）
1. **先加定语**：搜索实体时带上类别词。搜"文明起源"没结果时，换成"文明起源 游戏"立刻命中。
   技术类加"文档""教程""benchmark""issue"；新闻类加年份。
2. **多引擎交叉**：`web_search` 默认会依次尝试多个引擎。中文内容优先 Bing / 智谱；
   技术内容优先搜 GitHub / 官方文档。
3. **先搜索后抓取**：从结果里挑最相关的 2-5 个链接，用 `web_fetch` 读全文。
   摘要不足以支撑结论，必须读原文。
4. **源头优先**：官方文档 > 官方博客/Release Notes > 权威媒体 > 个人博客/论坛。
   同一事实至少两个独立来源。

## 信息处理
- 区分【事实】（有来源）与【推断】（你的判断），报告中要分开标注。
- 记下每条结论的来源链接，报告里给出引用。
- 遇到互相矛盾的信息：两个都列出来，说明分歧点，给出你倾向哪个及理由。
- 标注时效：这条信息是什么时候的？会不会已经过时？

## 报告结构
```
# 标题
## 一句话结论
## 关键发现（3-5 条，每条带来源）
## 详细分析
## 不确定与争议点
## 建议
## 资料来源
```

## 必须做到
- 搜不到就如实说"没有找到"，不要编造。用不同措辞再试 2-3 次（加定语/换语言/换引擎）。
- 不要用未经核实的记忆当事实。记忆里的信息可能过时，有用就查证。
- 报告长度与调研深度匹配，不要为了显得充实而注水。
